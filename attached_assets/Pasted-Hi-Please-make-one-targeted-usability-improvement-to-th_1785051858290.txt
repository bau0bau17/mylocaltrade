1. SERVICE OFFERED — AUTOCOMPLETE / SUGGESTIONS
--------------------------------------------------

The “Service Offered” field should no longer rely mainly on the trader typing the full service manually.

Add autocomplete suggestions while the trader types.

Examples:

Typing:
"ele"

should suggest things such as:
- Electrician
- Electrical installation
- Electrical repairs
- Emergency electrician

Typing:
"air"

could suggest:
- Air conditioning
- Air conditioning installation
- Air conditioning repair

Typing:
"boil"

could suggest:
- Boiler installation
- Boiler repair
- Boiler servicing

Requirements:

- Suggestions should appear dynamically below the input as the trader types.
- Matching should be case-insensitive.
- Match from the beginning of words and sensible partial text.
- Tapping a suggestion should immediately add it as a service chip/tag, using the existing chip UI.
- Prevent duplicate services.
- Keep the existing ability to add a custom service if the trader cannot find an appropriate suggestion.
- Trim/normalise accidental spacing and casing where appropriate.

Please use a sensible UK trades/services list rather than only a very small hard-coded list.

Examples should cover common categories such as:
Electrician, Plumber, Gas Engineer, Boiler Services, Heating Engineer, Air Conditioning, Builder, Carpenter, Joiner, Painter & Decorator, Roofer, Locksmith, Handyman, Cleaner, Gardener, Landscaper, Tiler, Plasterer, Bathroom Fitter, Kitchen Fitter, Drainage, Pest Control, Appliance Repair, CCTV/Security, etc.

Where possible, reuse the same service/category vocabulary already used elsewhere in MyLocalTrade search and enquiries so we do not end up with inconsistent naming.

--------------------------------------------------

The “Service Areas” field should also provide suggestions rather than requiring the trader to type the complete location manually.

"North"

- Northampton
- Northamptonshire
- North London
etc., depending on the available location dataset/provider.

Typing:
"Milton"

- Milton Keynes

Requirements:

- Provide autocomplete while typing.
- UK locations only.

- Tapping a suggestion adds it as a Service Area chip using the existing UI.
- Prevent duplicates.
- Keep manual entry available as a fallback if appropriate.
- Normalise location values consistently so search matching is reliable.

--------------------------------------------------
3. SERVICE AREAS MUST DRIVE CUSTOMER SEARCH
--------------------------------------------------

This is very important.

The Service Areas saved on the trader profile must be used when customers search by location.

Example:

Trader profile:
Service Areas:
- Milton Keynes
- Northampton

Customer searches:
Location = Northampton

That trader should be eligible to appear in the results, assuming the requested service also matches the trader's services and all normal visibility/verification rules are satisfied.

Likewise:

Customer searches:
Location = Milton Keynes

The trader should also be found.

Please inspect the existing customer trader-search implementation and make sure it uses the trader's Service Areas rather than relying only on the trader's business address.

Expected logic should broadly be:

requested service matches trader service
AND
searched customer location matches one of trader's service areas
AND
trader passes the existing visibility/status requirements

Do NOT expose the trader's private/full business address as part of this change.

4. LOCATION MATCHING / NORMALISATION
--------------------------------------------------

Please avoid brittle exact-string-only matching where possible.

For example, values should not fail simply because of casing:

"Northampton"
"NORTHAMPTON"

should be treated consistently.

Also trim whitespace and normalise stored/search values where appropriate.

If the current system already has postcode/location normalisation, reuse it.

Do not implement an overly broad fuzzy match that could return unrelated locations.
