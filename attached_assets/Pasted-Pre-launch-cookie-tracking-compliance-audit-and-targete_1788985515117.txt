DECISION RULE

IF the current public website/admin only uses strictly necessary or essential functional storage:

- DO NOT add a cookie consent banner.
- DO NOT create Accept/Reject UI.
- Correct the Cookie Policy only if it currently overstates analytics, advertising, or third-party cookie use.
- Make the policy describe the actual current implementation accurately.
- Explicitly report:
  “No cookie-consent banner is required by the current implementation.”

IF ANY NON-ESSENTIAL ANALYTICS / MARKETING / TRACKING IS ACTUALLY ACTIVE:

Implement the smallest compliant preference mechanism.

Required behavior:

1. Non-essential tracking disabled by default.
2. Clear first-visit choice:
   - Reject non-essential
   - Accept
   - Manage preferences
3. Reject must be as easy/prominent as Accept.
4. Categories should match ACTUAL technologies only.
5. Persist the choice.
6. Allow users to reopen/change/revoke preferences later.
7. No analytics/marketing script may initialize before valid consent.
8. Strictly necessary technologies remain enabled.
9. No dark patterns.
10. Do not reload unnecessarily if runtime toggling is safe.
11. If a reload is technically required to remove third-party state, explain it clearly.

CONSENT RECORDING

If a consent mechanism is required:

- store the minimum evidence needed;
- include consent version and timestamp;
- do not create unnecessary personal profiles;
- avoid backend persistence unless there is a clear operational/legal need;
- if client-side consent storage is sufficient, prefer that simpler model.

PUBLIC UI

If needed, add a visible “Cookie settings” / “Privacy choices” entry so consent can be changed later.

It should be accessible from the public footer/legal area.
