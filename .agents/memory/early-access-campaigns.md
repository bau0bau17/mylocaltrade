# Early Access campaigns — invariants

- **Two independent negative axes** on `early_access_registrations`: voluntary/admin unsubscribe (`unsubscribedAt`+`unsubscribeSource`) vs deliverability suppression (`emailSuppressedAt`+`emailSuppressionReason`: hard_bounce|complaint|blocked). Never conflate; the public form lifts NEITHER (email_suppressed also withholds confirmation emails), and only verified re-confirmation lifts a *user* unsubscribe.
- **Bulk sends use Brevo's MARKETING pipeline** (contact lists + email campaigns), never the transactional dispatcher. All real Brevo calls are gated on `MARKETING_BREVO_ENABLED=true` + a key; otherwise `BrevoMarketingDisabledError` before any network traffic — dev/tests can never create prod Brevo objects. Test sends (single copy to the acting admin only) are the one legitimate transactional-route use.
- **Batch idempotency contract**: recipients reserved queued→sending under FOR UPDATE SKIP LOCKED; the Brevo campaign id is stored on the batch row BEFORE sendNow. Recovery rule: pending batch WITHOUT brevoCampaignId → release to queued (provably unsent); WITH id → mark `recovered_assumed_sent` and NEVER resend. Duplicates are treated as worse than skips.
- **Snapshot vs re-check**: queue-time snapshot fixes WHO (immutable, typed `SEND TO N PEOPLE` phrase must match the server count computed under the campaign row lock); every batch re-checks live unsubscribe/suppression and downgrades instead of sending. Content is immutable once queued (draft-only PATCH, conditional update).
- **Quota is local + conservative** and now a configurable PLAN MODEL (`sendAllowanceModel()`): env-only knobs `BREVO_ACCOUNT_DAILY_CAP` (default 300, literal `none` = uncapped daily, e.g. paid plans), `BREVO_ACCOUNT_MONTHLY_CAP` (`none` default; a "5,000 emails" plan is 5,000/MONTH — set this, not the daily cap), `BREVO_MONTHLY_RESET_DAY` (1–28), `MARKETING_DAILY_SEND_CAP`, `TRANSACTIONAL_EMAIL_DAILY_RESERVE`/`_MONTHLY_RESERVE`. Bad values surface in `configIssues`, never silently. All numbers are LOCAL estimates — admin UI must keep the "Brevo's dashboard remains the source of truth" caption. Plan upgrade = env change + "send next batch"; no scheduler exists (deliberate; don't invent an in-memory cron). Test sends have BOTH a per-campaign limit and a GLOBAL/day limit (`TEST_EMAIL_DAILY_LIMIT`, Brevo's test allowance is account-global), both checked under the quota lock.
- **Unsubscribe tokens are stateless HMAC** (`u1.<id>.<sig>`, key derived from DEDICATED `EARLY_ACCESS_UNSUBSCRIBE_SECRET`, rotation via `_PREVIOUS` (verify both, sign with current only) — never SESSION_SECRET): nothing stored, no expiry (old email links must keep working), verify with timingSafeEqual, raw token never logged. Landing page `/unsubscribe` mirrors `/confirm-early-access` (GET inert, POST mutates, token stripped from history, no-store/no-referrer in serve.js). Per-recipient links in bulk mail ride Brevo contact attribute `EA_UNSUB_TOKEN`; Brevo's native `{{ unsubscribe }}` is also kept in the HTML (required by Brevo + keeps List-Unsubscribe).
- **Brevo webhook** (`/api/early-access/brevo-events`) auth is HEADER-ONLY: custom header `X-Webhook-Secret` = `BREVO_WEBHOOK_SECRET` (+`_PREVIOUS` rotation); query-string secrets deliberately rejected (URL/proxy-log leakage). 404 while unset. Only ever TIGHTENS state (unsubscribe/suppress/delivered), first-suppression-reason wins, idempotent conditional updates. Marketing-webhook event names: `spam`, `hardBounce`, `unsubscribed`, `delivered` (`blocked` exists only on the TRANSACTIONAL webhook type — classifier accepts it defensively but never select it in Brevo's marketing webhook UI).
- **Campaign audit events hold counts/ids/flags only** — never recipient lists, content, keys or tokens.
- **sendNow failure classification**: `BrevoApiError` 4xx = DEFINITE rejection → nothing sent: delete the never-sent draft campaign+list, release recipients to queued, batch failed (`BATCH_REJECTED` audit); `not_enough_credits` parks the campaign in `waiting_quota`. Only ambiguous failures (network/5xx) take the assumed-sent path. Never blur this line — it's what makes retry safe.
- **Temporary list cleanup lifecycle**: one Brevo list per batch would leak forever; cleanup (`cleanupBatchLists`) deletes the remote list only when the send can't be affected (batch failed, or batch sent AND Brevo reports campaign sent/archived/gone), tracked via `brevoListDeletedAt`/`cleanupAttempts`/`cleanupLastError` on the batch row. Idempotent (remote 404 = success), runs opportunistically after each batch + manual admin POST /cleanup; ≥3 failed attempts surface as `orphanedBrevoLists` warning. NEVER delete local recipients/audits/brevoCampaignId — Brevo objects only.
